## Decisions taken (and why)

1. **Minute convention (§8.2).** `m = floor((check-in − start) / 1 min)`: Present when `−opens ≤ m ≤ grace`, Late when `grace < m ≤ closes` (`m − grace` minutes), refused otherwise. "10:15" therefore covers 10:15:00–10:15:59 and "one minute after the grace period" (10:16) is late — matching the §8.2 example and the closing rule Phase 3 already used. Only the server clock decides; the browser's clock is never used.
2. **Biometrics are platform passkeys (WebAuthn)** with user verification required, discoverable credentials, no attestation; the device performs the fingerprint/face check and the server stores only a public key and counter (§4.5). Sign-in is usernameless, so it reveals no account.
3. **Enrollment needs a password or email-code session.** A biometric session can never enroll another device (no bootstrapping from a stolen device). Removing a device ends the sessions it opened.
4. **Check-in confirmation (§7.2).** A student with an enrolled device always confirms with a fresh assertion whose challenge is bound to that student and that visit, and always sends the location. For students without one, the Training Director chooses the fallback (documented choice, not a silent skip or block): **allow, marked "not confirmed with biometrics"** (default — devices without biometrics remain usable and faculty see the flag) or **refuse until enrolled**; and whether the location is required for those check-ins (default **required**). The policy is program-wide and applies from the next check-in (unlike timing, it is not copied into visits).
5. **Location is supporting context.** Stored with accuracy and the distance from the visit's coordinates for faculty review; never used to accept or refuse by itself (a reading can be spoofed, §7.2); not written to the audit log; not shown in the student's history.
6. **QR token = visit id + 128-bit HMAC-SHA256 tag** (43 URL-safe characters). Stable for the whole visit (print once), unforgeable for another visit, no personal data. `QR_HMAC_SECRET` is required in production; elsewhere a key derived from the JWT secret is used. Rotating the secret invalidates printed codes.
7. **Absences are insert-only.** Each run inserts ABSENT records for current group members without one (`ON CONFLICT DO NOTHING`) and marks the visit processed under a row lock, so overlapping runs and retries are harmless and a correction or check-in is never overwritten. Pages, dashboards and exports finalize a closed visit themselves, so figures never depend on the scheduler's timing. The job authenticates with `CRON_SECRET`, kept in Supabase Vault and read at run time (never in the job text); the endpoint answers 404 when no secret is configured.
8. **Who is expected:** the visit's groups' current members when the window closes. A student who checked in and later changed group keeps the record (shown as "left the group").
9. **Corrections (§8.4)** are possible once check-in has opened (not before — the record would pre-empt the student's own check-in), never for a cancelled visit, for current members of the visit's groups or students who already have a record. Late needs minutes (1–720); the reason is optional but recommended. The student is notified and sees the reason, never the corrector (§13 privacy pattern).
10. **One server clock.** An injectable `Clock` serves attendance, challenges and the visits service, so tests stand at any instant of a window; tokens and sessions keep real time.
11. **Exports** reuse one query for all formats and finalize absences first, so files equal the screens; caps of 10,000 rows (CSV/XLSX) and 3,000 (PDF). **Finding:** react-pdf's automatic page breaking grows quadratically (3,000 rows took 148 s); pages are now cut at a fixed number of rows (overflow still breaks safely), bringing 3,000 rows to about 13 s. The PDF leaves out the biometric column for width; CSV and XLSX include it. CSV is UTF-8 with BOM and neutralizes formula-like text; XLSX is right-to-left for Arabic.
12. **A student record with attendance cannot be deleted** (`STUDENT_HAS_ATTENDANCE`); history is kept (§16.1).
13. **Return after sign-in** (`?next=`) accepts only paths of this site; a scanned link survives sign-in, but a required password step or verification still comes first.

## Known limitations

- WebAuthn needs HTTPS (or `localhost`) and the phone's main browser; some in-app browsers (QR scanner views) do not support it — the check-in page says so.
- A synced passkey is one credential across the owner's devices (shown as "Synced passkey").
- Students without an account (imported, never signed in) can only be recorded by a correction.
- No advance "excused absence" before a visit opens (corrections start when check-in opens).
- PDF reports take about 13 s at the 3,000-row cap; the web relay allows 60 s, the API function 30 s.
